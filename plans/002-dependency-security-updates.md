## Why this matters

`pnpm audit --prod` reports 5 advisories (2 high, 2 moderate, 1 low), including
one on **drizzle-orm** — a direct dependency on the app's only data path.
Separately, every pnpm command prints
`[WARN] The "pnpm" field in package.json is no longer read by pnpm`, meaning
the `pnpm.overrides` block in `package.json` is **silently doing nothing** on
pnpm 10. Transitive vulnerabilities can't be pinned away until overrides live
where pnpm actually reads them (`pnpm-workspace.yaml`).

## Steps

### Step 1: Bump drizzle-orm

```
pnpm add drizzle-orm@^0.45.2
```

If pnpm reports a peer-dependency conflict with `drizzle-kit` or `drizzle-zod`,
bump those too (`pnpm add -D drizzle-kit@latest`, `pnpm add drizzle-zod@latest`)
and note the versions in your report.

**Verify**: `pnpm typecheck` → exit 0. If typecheck fails inside
`src/lib/db/schema.ts` or the routers, see STOP conditions.

### Step 2: Verify no schema drift from the toolchain bump

```
pnpm db:generate
```

**Verify**: output indicates no schema changes; `git status` shows no new file
under `src/lib/db/migrations/`. If a migration WAS generated, delete it,
`git checkout` any modified migration metadata, and record this in your report
(STOP condition).

### Step 3: Move overrides to pnpm-workspace.yaml and pin transitive vulns

Remove the entire `"pnpm": { ... }` block from `package.json` (lines 66–71 in
the current state). Do NOT migrate the `@types/react` pins — they are stale.

Append to `pnpm-workspace.yaml`:

```yaml
overrides:
  ws: '>=8.21.0'
  postcss: '>=8.5.10'
  '@babel/core': '>=7.29.1'
```

Then `pnpm install`.

**Verify**:
- `pnpm install` → exit 0 and no `[WARN] The "pnpm" field` warning.
- `pnpm audit --prod` → 0 high, 0 moderate (a residual `low` is acceptable;
  note it in the report).

### Step 4: Full gate

**Verify**: `pnpm typecheck` → exit 0; `pnpm lint` → exit 0; `pnpm build` →
exit 0.
